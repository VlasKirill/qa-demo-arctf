# Чек-лист ручного тестирования Auth Demo

## Регистрация

### Позитивные сценарии
- [pass] Регистрация с валидными данными (email, username, password)
- [pass] Проверка, что пользователь создан в БД
- [pass] Сообщение об успешной регистрации

### Негативные сценарии
- [pass] Регистрация с уже существующим email => ошибка 400
- [pass] Регистрация с невалидным email (без @, бед домена) => ошибка валидации
- [failed] Регистрация с пустым username => ошибка валидации
- [failed] Регистрация с некорректным паролем (< 8 символов) => ошибка валидации
- [pass] Регистрация с спецсимволом в username => проверить поведение

### Граничные значения
- [failed] Email ровно 254 символа (максимум по RFC)
- [pass] Username ровно 1 символ
- [pass] Username ровно 50 символов (если есть ограничение)
- [pass] Password ровно 8 символов (минимум)
- [blocked] Password ровно 128 символов (максимум)

## Авторизация

### Позитивные сценарии
- [pass] Вход с валидными credentials
- [pass] Получение JWT токена
- [pass] Токен содержит корректный email в payload
- [pass] Токен имеет срок действия (exp claim)

### Негативные сценарии
- [pass] Вход с несуществующим email => ошибка 401
- [pass] Вход с неверным паролем => ошибка 401
- [pass] Вход с пустым email => ошибка валидации
- [pass] Вход с пустым паролем => ошибка валидации

## Защитные эндпоинты (/me)
- [pass] Запрос с валидным токеном => 200 OK
- [pass] Запрос без токена => 401 Unauthorized
- [pass] Запрос с истекшим токеном => 401 Unauthorized
- [pass] Запрос с невалидным токеном => 401 Unauthorized
- [failed] Запрос с токеном удаленного из БД юзера => 401 Unauthorized 
- [pass] JWT не содержит password или password_hash
