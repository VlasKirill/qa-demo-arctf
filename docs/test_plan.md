# Test-plan Auth Demo

## Введение

### Цель документа
Определить стратегию, объем, ресурсы и график тестирования системы регистрации и авторизации пользователей.

### Общие сведения о системе
Веб-приложение для регистрации/авторизации пользователей. Включает frontend (HTML, CSS, JS) и backend (FastAPI, SQLite). Реализует JWT-аутентификацию для защищенных эндпоинтов.

## Объект тестирования

**Тестируется:**
1. API-эндпоинты:
    - POST /register (регистрация пользователя)
    - POST /login (авторизация пользователя)
    - GET /me (получение данных текущего пользователя)
    - GET /health (проверка работоспособности)
2. UI-компоненты:
    - Форма регистрации
    - Форма авторизации
    - Переключение между вкладками Login/Register
    - Отображение сообщений об ошибках/успехе
    - Индикатор статуса API (ONLINE/OFFLINE)
    - Сохранение токена в localStorage
3. База данных
    - Корректность записей пользователей
    - Хеширование паролей (bcrypt)
    - Уникальность email
4. JWT-токены
    - Структура токена (header, payload, signature)
    - Срок действия (Claim exp)
    - Валидация подписи

**Не тестируется:**
- Нагрузочное тестирование
- Тестирование безопасности (SQL injection, XSS, CSRF)
- Кроссбраузерное тестирование (только FireFox)
- Мобильная адаптация
- Интеграция с внешними сервисами (email, payload)

## Стратегия тестирования 

**Виды тестирования:**
1. Функциональное тестирование:
    - Позитивные сценарии (успешная регистрация, авторизация)
    - Негативные сценарии (невалидные данные, дубликаты)
    - Граничные значения (длина пароля, email)
2. Интеграционное тестирование:
    - Взаимодействие фронтенд-бэкенд
    - Взаимодействие бэкенд-БД
    - Работа JWT-токенов с защищенными эндпоинтами
3. Регрессионное тестирование:
    - Автоматизированные тесты для критических сценариев
    - Smoke-набор после изменения кода
4. UI-тестирование:
    - Ручная проверка пользовательских сценариев
    - Проверка клиентской валидации
    - Проверка работы с localStorage
5. API-тестирование:
    - Проверка статус-кодов
    - Валидация JSON-схем ответов
    - Проверка заголовков и параметров запросов
**Подход к тестированию:**
- Ручное тестирование для исследования и проверки UI
- Автоматизация для повторяющихся и регрессионных сценариев
- Риск-ориентированный подход: критические сценарии (регистрация/авторизация) покрываются на 100%

## Entry/Exit Criteria

**Критерии старта (Entry Criteria):**
- Бэкенд и фронтенд развернуты в тестовом окружении
- Docker-container запущены и доступны
- База данных инициализирована
- API документация (Swagger) доступна по адресу /docs
- Тестовые данные подготовлены (валидные и невалидные email и пароли)

**Критерии завершения (Exit Criteria):**
- Пройдено 100% критических тест-кейсов (регистрация, авторизация, /me)
- Пройдено не менее 90% тест-кейсов общего приоритета
- Нет открытых дефектов с серьезностью Critical или High
- Все найденные дефекты задокументированы в баг-трекере
- Автоматизированные тесты прохрдят без ошибок
- Отчет о тестировании составлен и передан стейкхолдерам

## Ресурсы и окружения (Environment)

**Техническое обеспечение:**
- Операционная система: WWindows 11/Ubuntu 22.04
- Браузер: Mozilla FireFox 159.0.1+ (автотесты так же на chromium)
- Docker: Docker Desktop 4.25+
- Python 3.11
- HTML/CSS/JS

**Тестовые стенды:**
- Локальное окружение:
    1. Frontend: [http://localhost:3000]
    2. Backend API: [http://localhost:8000]
    3. Swagger Docs: [http://localhost:8000/docs]

**Инструменты:**
- Тестирование API: Postman, Swagger UI
- Автоматизация: Pytest, PlayWright
- База данных: DBeaver (SQLite), docker exec для прямого доступа
- Баг-трекинг Jira (или Markdown-файлы)
- Отчетность: Allure Report
- Контроль версий: Git, GitHub

**Тестовые данные:**
- Валидные email: test@example.com, qa_test@test.com
- Валидные пароли: StrongPass123!, TestPassword456!
- Невалидные данные: no_domen@, @no.email, Short1!, пароли и email длиной более 72 и 252 символов соответственно

## Отчетность и метрики (Reporting)
**Формат отчетности:**
- *Ежедневный статус*: Краткий отчет в чат команды (найденные баги, заблокированные тесты)
- *Итоговый отчет*: Документ с метриками качества после завершения тестирования

**Метрики качества:**
1. Покрытие тест-кейсами: % выполненных тест-кейсов от общего количества
2. Плотность дефектов: количество найденных багов на 100 тест-кейсов
3. Серьезность дефектов: распределение багов по критичности (Critical/High/Medium/Low)
4. Время выполнения: среднее время прогона автотестов
5. Стабильность тестов: % успешных прогон автотестов без flaky-ошибок

**Частота отчетности:**
- Ежедневно: статус в чат (5-10 минут)
- По завершении этапа: письменный отчет с метриками
- По завершении тестирования: итоговый отчет с рекомендациями

**Инструменты отчетности:**
- Allure Report: детальные результаты автотестов с вложениями (скриншоты, логи)
- Jira: статусы багов и тест-кейсов
- Confluence: документация и итоговые отчеты
